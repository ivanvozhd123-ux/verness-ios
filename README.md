# verness / iOS

Нативный SwiftUI-проект для iOS 17+. Исходники приложения, расширения Island,
XCTest и музыкального сервера находятся в этой папке. Windows и Android не меняются.

**На Windows нельзя собрать или подписать IPA:** необходимы macOS, Xcode и iOS SDK.
Этот проект подготовлен на Windows и здесь не проходил компиляцию Apple SDK.
Проверки, которые удалось выполнить, указаны в `VALIDATION.md`.

## Открыть на Mac

1. Установи Xcode 15 или новее, открой `verness.xcodeproj`.
2. Выбери схему `verness` и iPhone Simulator. Нажми Run.
3. Для настоящего iPhone выбери свою Team в Signing & Capabilities **у обоих**
   targets: verness и VernessIsland. При необходимости задай собственные Bundle ID,
   сохраняя префикс приложения у расширения.
4. Для распространения на устройство используй Product → Archive и подходящий
   способ подписи/экспорта в Xcode. Фальшивого или неподписанного «готового IPA»
   в этом проекте нет.

Сборка симулятора из терминала: `bash scripts/build.sh`.
Тесты: `bash scripts/test.sh`. Результат сборки — в `build/`.
`scripts/generate_project.py` детерминированно пересоздаёт Xcode-проект из файлов
App/, Shared/, Island/, Tests/. После ручных изменений signing-настроек в Xcode
не запускай генератор без сохранения своих настроек.

Если создать отдельный GitHub-репозиторий с содержимым этой папки в корне,
`.github/workflows/ios.yml` выполнит сборку и XCTest на macOS. Workflow здесь не запускался.

## Что реализовано

- SwiftUI-экраны verness: главная, Пульс, поиск, библиотека, плейлисты, настройки.
- Импорт через Files/iCloud Drive и «Открыть в verness»; аудио копируется в библиотеку.
- Избранное, редактирование названия/исполнителя и обложки через Photos Picker.
- Очередь, shuffle без повторов внутри прохода, off/all/one repeat, перемотка.
- AVAudioEngine + AVAudioPlayerNode + 10-полосный AVAudioUnitEQ + TimePitch.
  Эквалайзер, предусиление, защита от перегруза, скорость 0.5–2×, громкость.
- Аудиосессия playback, фоновый режим, Control Center и экран блокировки,
  обработка аудиопрерываний, отключения наушников и сброса медиасервиса.
- Онлайн-трек сначала загружается в кеш, затем проигрывается тем же движком,
  что и локальный файл. Это обеспечивает работу EQ для онлайн-музыки.
  Есть фоновая URLSession-загрузка, отмена при переключении и подготовка
  следующего трека. Кеш ограничен примерно 300 МБ, один трек — 100 МБ.
- Lyrics: LRC-таймкоды, offset, несколько таймкодов строки, подсветка, переход
  по строке и следование за воспроизведением. Обычные тексты и отсутствие текста
  обрабатываются отдельно.
- Пульс: выбор до 40 артистов, свои имена и подгрузка результатов по мере игры.
- Светлая/тёмная темы, акценты, RU/EN, сохранение библиотеки и настроек в JSON.
- Island через ActivityKit: компактный, минимальный и развёрнутый Dynamic Island,
  Live Activity на экране блокировки и AudioPlaybackIntent-кнопки управления.

Динамический остров появляется только на совместимом iPhone. На остальных
устройствах доступна Live Activity на экране блокировки. Её показ зависит от
системного разрешения и ограничений iOS. Произвольное плавающее окно поверх
любого приложения, как в Android, здесь не реализуется. В приложении есть
компактная нижняя панель и полный экран трека.

## Онлайн-музыка и сервер

На iOS нельзя просто запустить yt-dlp.exe или Android Python-бинарник.
В этой версии yt-dlp выполняется на **отдельном компьютере/сервере**.
Внешний сервер не создан и не развёрнут автоматически. Без него локальная
библиотека и воспроизведение продолжают работать, онлайн-поиск показывает
предложение настроить подключение.

На Windows в корне исходного проекта можно использовать уже имеющийся
`modules/mus/yt-dlp.exe` и Node.js. Для Python нужен 3.10 или новее.

```powershell
$env:VERNESS_API_TOKEN = [guid]::NewGuid().ToString('N')
python ios/Server/server.py --host 0.0.0.0 --port 8766
```

На iPhone в «Настройки → Сервер музыки» укажи адрес компьютера в своей Wi-Fi
сети, например `http://192.168.1.10:8766`, и значение VERNESS_API_TOKEN.
Выбери «Сохранить» и «Проверить подключение». Разреши локальную сеть при запросе
iOS. Для доступа извне нужен свой HTTPS-адрес; приложение отклоняет публичный
HTTP. Ключ сохраняется в Keychain, в обычный JSON он не записывается.

Сервер не меняет firewall. Доступ из Wi-Fi нужно разрешить в Windows отдельно.
По умолчанию без `--host` сервер слушает только 127.0.0.1.
Не выставляй частный HTTP-сервис напрямую в интернет: используй HTTPS reverse proxy
и собственный ключ доступа. В логах запросов токены не печатаются.

На Linux/Mac: установи Node.js 22+, создай Python venv и выполни
`pip install -r Server/requirements.txt`. Затем запусти server.py с теми же
параметрами и переменной окружения. Есть Dockerfile; контейнер запускается
с `VERNESS_API_TOKEN` и опубликованным портом 8766, за своим HTTPS proxy.

Сервер предоставляет health/search/resolve/lyrics и потоковый M4A proxy с Range.
Search и resolve требуют Bearer-ключ; аудио использует случайную подписанную
ссылку сроком около 15 минут. URL источника и ключ не записываются в библиотеку.
Поддержка конкретного трека зависит от источника; запрашивается AAC/M4A,
совместимый с нативным аудиодекодером iOS.

Проверка сервера: `python -m unittest discover -s ios/Server -p test_server.py -v`.
Отдельная сетевая проверка: `python ios/Server/check_live.py` — она обращается
к реальному источнику и читает небольшой диапазон аудио.

## Ограничения первой версии

Нативный запуск, качество звука/EQ, Control Center, прерывания, расход батареи,
AirPlay/Bluetooth и Dynamic Island требуют проверки в Xcode и на iPhone.
История текущей очереди после завершения процесса не восстанавливается,
аватарки артистов пока заменены инициалами, реакции анимации на реальный бит нет.
Успешные проверки сервера не означают, что нативная iOS-сборка уже прошла тесты.

Основные API: [AVAudioEngine](https://developer.apple.com/documentation/avfaudio/avaudioengine),
[ActivityKit](https://developer.apple.com/documentation/activitykit),
[AudioPlaybackIntent](https://developer.apple.com/documentation/appintents/audioplaybackintent).
Зависимости сервера: [yt-dlp](https://github.com/yt-dlp/yt-dlp), тексты —
[LRCLIB](https://lrclib.net/docs).
